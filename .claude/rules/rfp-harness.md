## 🎯 1. 하네스 목적 및 AI 행동 규칙

본 문서는 Claude Code가 Eval-ATS의 코드·산출물을 생성할 때 **RFP 요구사항의 명확성, 추적성, 검증성**을 보장하기 위한 시스템 프롬프트 가이드다. `dev-schedule.markdown` / `sprint1.markdown`에 정의된 스프린트 일정과 충돌하는 산출물을 만들지 않는다.

### Claude Code 필수 준수 규칙 (Rule Set)

1. **[명확성]** 모호한 표현 금지. "검색을 빠르게 한다" → "지원자 10만 건 규모에서 필터 조합 검색 응답 1초 이내".
2. **[원자성]** 복합 기능은 단일 요구사항 ID 단위로 독립 검증 가능하도록 모듈화 작성한다. 하나의 PR/커밋이 여러 요구 ID를 걸치지 않는다.
3. **[추적성]** 생성되는 모든 코드·테스트·설정 파일 상단에 관련 요구사항 ID를 주석으로 명시한다.
   - Python: `# Requirement ID: SFR-001`
   - TypeScript/TSX: `// Requirement ID: SFR-001`
4. **[검증성]** 요구사항별 검수 기준(Acceptance Criteria)에 명시된 단위/통합 테스트 코드를 함께 생성한다.
5. **[일정 정합성]** 작업을 배치할 때 `sprint1.markdown` 형식(날짜 · 담당 · 작업 내용 · 상태)의 스프린트 로그와 담당자를 그대로 따른다 — 임의로 담당자를 재배정하지 않는다.

## 🏗️ 2. 시스템 아키텍처 및 5인 R&R 구성

```
[ Frontend: Vercel ]                    [ Backend: AWS ]
Next.js/React (TS)  ---REST/Proxy--->   FastAPI (EC2)
├── 공고/지원자 화면, 로그인             ├── 공고/지원자 CRUD, 단계 전환 로직
└── 모바일 반응형                        ├── 검색·필터 API (PostgreSQL)
                                         ├── GraphRAG 파이프라인 · 정량 평가
                                         └── 이력서 업로드(S3) · 알림(SES/SQS)

[ Infra/Quality ]
Docker · GitHub Actions CI/CD · EC2 배포 · API 테스트 · QA
```

### 5인 개발 R&R 및 담당 모듈

| 담당자 | 역할 | 책임 범위 | 기술 스택 |
| :--- | :--- | :--- | :--- |
| **이재우** | 백엔드·총괄 | 공고/지원자 CRUD, 단계 전환 로직, DB 스키마 | FastAPI, PostgreSQL |
| **이우정** | 검색·데이터 | 검색/필터 API, 인덱스 튜닝, 더미 10만 건 생성 | PostgreSQL, SQL |
| **김민아** | 파일·알림 | 이력서 S3 업로드, 지원 폼, 메일 발송 큐 | AWS S3, SES, SQS |
| **박소연** | 프론트엔드 | 지원자 목록/상세, 공고 관리, 로그인, 모바일 화면 | React, TypeScript, Vercel |
| **진수택** | 인프라·품질 | Docker, CI/CD, AWS 배포, API 테스트, QA | Docker, GitHub Actions, EC2 |

작업이 이 표의 담당자 경계를 넘나드는 경우(예: 검색 API가 GraphRAG 파이프라인과 맞닿는 지점), 어느 쪽 담당자 코드에 손을 대는지 먼저 밝히고 진행한다.

작업 완료 후 Claude Code가 스스로 수행할 검증 루틴:

- [ ] **[추적성 검증]** 구현된 모든 소스 파일 상단에 `Requirement ID: SFR-XXX` 주석이 있는가?
- [ ] **[모의 검수]** `pytest tests/`, `npm run test` 수행 시 각 요구 ID의 검수 기준 통과 여부가 출력되는가?
- [ ] **[CORS/보안]** 로컬 프론트엔드(localhost:3000)에서 백엔드(localhost:8000) 호출이 정상 동작하고, 미인증 요청은 차단되는가?
- [ ] **[일정 정합성]** 구현한 작업이 `sprint1.markdown` 등 스프린트 로그의 담당자·날짜와 일치하는가? 불일치 시 로그를 함께 갱신했는가?
- [ ] **[문서화]** `.env.example`에 RDS, S3, SES/SQS, GraphRAG 관련 접속 정보가 빠짐없이 정의되어 있는가?
